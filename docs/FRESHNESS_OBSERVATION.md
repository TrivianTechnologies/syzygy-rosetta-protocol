# Freshness observations v1

This optional draft implements the authenticated checkpoint and continuity requirements from Zixuan Guo’s Week 8/9 delegated-authority research. Its result describes the source read at a specific point. It confers no authority, expresses no consent and makes no claim about corrective uptake.

A trusted host enrolls the issuer’s Ed25519 public key, domain (issuer, epoch, relationship and scope) and initial cursor out of band. Each online exchange uses a random 256-bit challenge and the verifier’s durable floor. The subject is a SHA-256 digest of the consumer’s exact, versioned evidence representation. The issuer must independently resolve the authoritative comparison. It must verify that both parts of the supplied floor belong to its current histories, including when it returns a larger revision. A label or larger number alone cannot establish extension.

The query is the ordered JSON array `[profile,domain,subject,nonce,floor]`. A cursor is `[source_revision,event_id,head_sha256,publication_revision,publication_sha256]`. Absent publication is revision zero with 64 zeroes. The reply is `[[query,cursor,status],signature_hex]` with canonical compact ASCII JSON of the first element signed using Ed25519. Domain labels are printable ASCII. Digests are lowercase hex. Source revisions are authority-assigned positive integers below 2^53. Publication revisions use the same bound. All wire arrays have fixed length. A host transport must bound message sizes, reject duplicate or malformed representations, authenticate callers, and implement connection/read deadlines.

The four issuer statuses are current, stale, unpublished and conflict. A verified current response is reported as current_at_check. The verifier rejects wrong challenges, wrong signatures, delayed responses, rollback and conflicting heads. It updates its floor transactionally and durably quarantines a signed history contradiction. Concurrent exchanges can return floor_changed and require a fresh round trip. Recovery from quarantine requires independent administrative resolution and an explicitly enrolled epoch.

Bounded previews are opt-in, content-free, process-local, scoped to the same subject and floor and limited to 1,000 milliseconds measured from the original challenge. A preview that survives a temporary outage can describe a superseded state. Strong admission never consumes these receipts. Use a trustworthy monotonic clock that accounts for suspend, or discard preview state and active exchanges across suspend. Deleting or rolling back the entire verifier database defeats its rollback memory. Protect the floor independently of authority backups. Cross-client equivocation requires additional auditing or coordination. No production identity, transport, key custody, rotation or consensus service is supplied.

Install the protocol's freshness extra to use the codec and verifier. enroll=True is a provisioning operation. Normal startup uses the default reopen-only behavior. Fail closed on enrollment, storage or transport errors. For deployment profiles, specify which commit is authoritative, how the publisher reads it and where the effect becomes irrevocably admitted.
